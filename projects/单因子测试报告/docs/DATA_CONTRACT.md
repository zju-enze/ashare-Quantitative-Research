## 2. 所需源数据与字段语义

已从上传代码确认的文件名仅用于定位；其他文件名不猜测。实际列名不同时建立显式映射，不改写原始文件。

| 数据对象 | 已知文件/入口 | 必要字段或语义 | 主要检查 |
|---|---|---|---|
| 交易日历 | 具体文件名待定位；现代码用上证综指日期 | 日期、是否交易日；如有交易所列须说明 | 真月末与下一交易日；不能由截断文件最大日期替代 |
| 股票生命周期 | 文件名待定位 | 股票代码、证券类型/交易所、上市日期、退市日期、历史状态 | 全部A股边界；退市股票历史是否保留；不只用当前上市名单 |
| 日行情 | 文件名待定位 | 股票代码、交易日、收盘价 | 入场/退出日可用性、零/负价、重复键、停牌和数据漏失区分 |
| 日度估值 | daily_basic.parquet | ts_code、trade_date、pb、total_mv、circ_mv；close可从日行情映射；pe_ttm是原程序额外读取的非必要字段 | 本项目主因子只用pb；字段定义、单位、有效性、整行缺失 |
| 累计复权因子 | adj_factor.parquet | ts_code、trade_date、adj_factor | 与价格端点匹配、有限且为正、公司行为附近抽查 |
| 历史名称/风险状态 | loader.load_namechange() | ts_code、name、start_date、end_date及语义 | ST、*ST、PT等的确切生效区间；月中摘帽边界 |
| 停复牌 | 文件名待定位 | 股票代码、停牌日或区间、复牌日、全日/收盘交易状态 | 入场日是否停牌；期末停牌对应估值原因 |
| 指数历史成员 | index_weight.parquet | index_code、con_code、trade_date；可用时记录权重 | 000300.SH、000905.SH分别检查；快照日期与生效日期不能混淆 |
| 历史行业 | industry_sw_member.parquet | ts_code、l1_name、in_date、out_date | 行业版本、端点开闭、覆盖、重叠；禁止当前快照回填 |
| 指数日行情 | loader.load_index_daily() | 指数代码、trade_date、close及指数类型 | 与股票同端点；价格指数或全收益指数；缺失不得补0 |
| PB来源说明 | 本地说明/供应商原始文档，位置待核实 | 净资产口径、股本/市值口径、公告日、修订处理 | 支持“历史日度PB倒数”的准确描述 |
| 自行重构PB的备选数据 | 本轮未提供，不预设本地有无 | 归母权益、报告期、实际公告日期、更正版本、当时总市值 | 仅在确有需要时使用；不自动扩大为财报数据库工程 |

不要因为本项目选BP，就要求EP字段完整；也不要为了比较BP/EP绩效临时新增另一个主因子。

## 3. 读取和预检的最小粒度

先读schema、日期和分区摘要，再对异常有针对性抽样。无需把1.44GiB课程数据或全部交易记录复制进项目。

每个输入记录：

- 已核实绝对路径、格式、大小、实际日期范围、主键、关键列和单位。
- 数据更新时间或版本信息（如有）；没有就明确没有。
- 轻量摘要；正式运行再按成本合理的方式记录文件校验值或版本指纹，避免每轮无必要重复扫描全库。
- 历史真实性证据：源说明、实际公告/成员区间核对、仍未验证部分。

日期覆盖至少按年份/月和股票池检查，不能只看全表min/max。指数成员覆盖须按两个指数分别检查，不能依靠总日期数大于24作为充分条件。

## 4. 日期表要求

每个截面一行，至少包含：

| 字段 | 含义 |
|---|---|
| signal_month / signal_date | 信号所属月份与真实月末交易日 |
| entry_date | 信号日之后首个交易日 |
| exit_date | 下一月末之后首个交易日 |
| holding_month | entry_date所在月份，供C3年度归属 |
| signal_complete | 信号截面是否完整 |
| holding_complete | 共同数据截止日是否覆盖本期退出日 |
| calendar_source | 日历来源 |
| missing_endpoint_reason | 日历、股票价格、指数、复权等具体缺口 |

这里的字段是项目数据契约，可映射为其他清晰名称。必须保留三日期语义，不只使用ym字符串解释全部时间。

若某源截止2026-02-13，不得把它认作二月月末。最后完整评价期取决于所有必要源的共同覆盖；不能只用估值表的截止日期。

## 5. 股票样本的四层状态

### U：历史合格目标池

先重建信号日的全部A股或历史指数成员；按规范剔除ST/PT及入场日停牌个股。入场日停牌是附录明确的执行资格条件，应与信号时点信息区分记录。历史名单不得依据未来退市、未来收益或样本末端存活情况回筛。

### F：因子有效样本

在U内左连接信号日估值。正且有限pb才构造BP。覆盖分母保留没有估值行、pb缺失及pb非正的合格股票；原因分别计数。

### S：预处理与分层样本

在F内核实行业、总市值和回归权重等控制信息。缺失控制变量按既定政策处理并披露；不能悄悄把未知行业当作真实行业而宣称完成全部行业控制。S构建后完成预处理并冻结因子值、分层及基准成员。

### Y：结果可观测状态

为已经冻结的S连接入场/退出复权价与收益，记录是否可评价及原因。Y不能反向决定S。

回归/IC可能因响应缺失只在可观测子样本上估计，须报告损失和选择限制；分层已持有股票的权重不能因未知结果被重新平均。无法可靠估值的时期不能作为完整绩效。

## 6. 建议保留的样本流转字段

按股票池与信号期记录以下数量。数量名称可调整，定义不能随图表变化：

- 历史成员数、股票类型/上市状态合格数。
- ST/PT排除数、入场日停牌排除数、最终U人数。
- 估值行缺失数、pb缺失数、pb非正数、非有限值数、有效BP人数F。
- 行业缺失数、市值缺失/非正数、重复记录处理数、最终S人数。
- 各层人数、并列值数、被截尾人数及必要预处理诊断。
- 入场价格缺失数、退出价格缺失数、复权缺失数，分别标停牌、退市、漏数及尚未查明。
- 回归和IC实际使用数、各层已知权重占比、收益是否完整。

排除原因可能重叠时，必须明确是顺序互斥漏斗还是可重叠计数；不要把可重叠原因相加来推导剩余人数。

## 7. 历史区间与缺失处理

- 行业成员、名称与指数资料的区间开闭依据源字段语义确认；不默认所有out_date都包含或都不包含。
- 历史快照允许使用不晚于信号日、确实仍有效的最近一期；“不晚于”本身不证明快照仍完整。
- 同一股票同日多条行业记录应调查。不能仅保留最新in_date就把所有重叠解释为正常。
- 只有已知停牌且有合理价格延续规则时才讨论期末估值；绝不把所有未知收益统一填0。
- 退市价格缺失不等于零损失，也不自动等于100%损失；根据已获资料建立可解释规则。
- 若确需缩短可靠窗口，依据事先的数据质量和完整性标准确定，并记录排除范围；不得查看收益好坏后挑选年份。

## 8. 数据预检的交付边界

P1应产生实际检查摘要，而非漂亮但无证据的“数据质量合格”声明。每条结论至少有源文件/字段、检查范围、观察事实和影响。

对于历史PB点时性，区分：有直接时点证据；只有供应商定义和有限抽样支持；尚未证实。报告采用与证据相符的措辞。若无法支持严格点时性，不得写“已自行按公告日完整重构”，但可保留已核实的历史字段研究并明确限制。
