# 分阶段执行计划

状态：计划已编制；实际执行进度以[PROJECT_STATUS.md](PROJECT_STATUS.md)为准。统计口径以[RESEARCH_SPEC.md](RESEARCH_SPEC.md)为准，计划本身不代表阶段通过。

## 执行原则

- 按用户当轮指定的阶段范围推进。阶段通过意味着证据条件满足，不要求重复人工批准。
- 完成一个阶段即解释本阶段回答的问题；不要把所有检查压到报告写作之后。
- 输入不足时完成可继续的部分，列明具体文件/字段/时期及影响。不得把“没有上传”写成“本地不存在”。
- 只有P4以后才产生主实证结论；P0–P3的数量、缺失率等属于数据核查或诊断，不得包装为因子有效性。
- 以下文件路径是未来产物约定，不表示它们现在存在；目录按需创建，不生成一批空壳文件冒充进度。

## P0：接入项目与核实环境

**问题：我们正在操作哪个项目，读的是哪套程序和数据？**

动作：

1. 核实项目根目录、父级仓库规则、工作区现有文件，保留用户已有内容。
2. 定位课程教材、现有环境与qfbook；检查实际导入路径。用户上传README描述Python3.11及独立环境，但仍需本地验证。
3. 比较本地single_test.py的SHA-256与IMPLEMENTATION_REVIEW登记摘要。一致则确认同版；不一致则重新核对本地行为与审阅事项。本包不附原始源码，只有取得快照才做逐行差异比较；否则不宣称精确diff已完成，也不阻塞其余预检。只在指定课程范围查找报告生成脚本，未找到时记录检索范围，不推断全盘不存在。
4. 检查实际可用的学术skills及来源，记录读取入口。无匹配skill不阻塞数据工作。

产出：

- PROJECT_STATUS中的真实路径、环境/源码标识、教材版本、技能可用性。
- 源文件定位清单；必要时记录到outputs/preflight/source_inventory.csv。

通过条件：能够明确定位教材与现有实现，确认数据读取位置和本轮操作范围。若路径不可访问，提供可复核缺口，不伪造预检结果。

## P1：数据预检与方法冻结

**问题：现有数据能否支持附录指定研究，而不仅是“文件存在”？**

动作：

1. 按DATA_CONTRACT检查所需字段、键唯一性、逐期覆盖、日期范围与关键端点。
2. 查明PB分子与历史口径；区分负值、零值、非有限值和缺失。
3. 核对历史股票生命周期、ST/PT、停复牌、指数成员、行业区间。抽样检查状态变化附近日期。
4. 生成真实交易日历上的信号/入场/出场日期表；确定诊断和绩效各自可用范围。
5. 形成按股票池、月份的样本数量流转，列出未来收益缺失的具体原因及可解决程度。
6. 在未查看BP绩效的前提下，冻结可以落实的项目默认；不能落实的条目标清楚。

产出：

- outputs/preflight/data_inventory.csv：文件与字段可用性。
- outputs/preflight/calendar_audit.csv：三个日期、端点状态和是否完整。
- outputs/preflight/sample_flow.csv：逐步样本数量，不含推测结果。
- outputs/preflight/preflight_findings.md：已证实事实、尚待核实和建议处理。
- PROJECT_STATUS的方法版本/冻结记录。

通过条件：

- 正式股票池与成员时间范围可重建；不存在被隐瞒的当前快照或市值代理。
- 最终完整持有期有明确证据，未来缺失不会用于反向构造持仓。
- 主要未决数据问题具有处理政策；仍会改变结论的缺口明确阻断相应结果。

预检不要求先证明因子有效。若历史字段的点时性只能部分核验，应准确记录证据等级和结论限制，不冒称自行完成财报重建。

- 父仓库`.local/monthly.parquet`与`panel.parquet`是同源月度派生缓存，包含旧过滤和静态行业，不是新的历史日价或行业证据。

- 8,422个受影响股票-期涉及2,547只股票；去重后为7,434个缺失价格键（2019年前6,795个、2019年起639个），另有71个缺失复权键。它们包含真实停牌、改码、退出上市等情形，不能直接当成下载任务数量。证据：`outputs/preflight/repair_local_review.json`。

**1. 先统一证券身份。** 用本地基础资料、历史名称、三份旧代码probe和原日线核对旧码、新码及生效区间。区分同一证券改码与吸收合并/终止上市，不能仅按名称或尾号直接拼接。身份对应修正后重新分类行业、停牌与端点缺口；本地映射证据不足时才定向查询交易所或原供应商的历史改码表。

**2. 恢复历史成员和行业。**

**3. 修复停牌识别。** 关联本地S/R、日内停牌时段、原日行情及已取得的BaoStock状态。只有可信的起始停牌与后续复牌证据、适用日期及期间行情一致时，才重建缺失停牌区间并标注“区间推导”；不能仅凭无报价推断停牌。2015年前及2015–2018的剩余缺口按受影响代码/日期批次补资料，核对接口返回限量，不能把截断结果当完整历史。新旧代码先对应，不能直接把旧码S记录连接到同尾号新码。

**4. 把价格补数与估值政策分开。**

- 入场缺价：证实入场停牌，按附录更新U；证实可交易但源数据漏行，才补该日价格。不能因缺价直接删股。
- 退出停牌：没有实际成交价时，按RESEARCH_SPEC第7节，在状态和公司行为证据支持下制定教材级估值延续政策，单独保存估值与真实交易价格。不能把延续估值称作可成交价，也不能直接把整期收益填0。
- 退出上市/改码：先解决身份问题；真正退市、吸收合并等查本地终点和对价资料，不足时定向查交易所/公司公告。无法核实的终值继续标为未解决，不默认0或-100%。
- 纯数据漏失：上述分类后，仅补剩余精确的证券、日期和字段。优先同源日价及复权资料；第二来源要核对重叠日期与复权体系，不能直接拼接不同体系的因子数值。

**5. 核实BP定义及解释边界。** 先用本地daily_basic、财务公告日期、权益与股本检查，4条流通市值内部不一致记录单独处理。只有字段定义或具体异常无法本地说明时，才查询供应商原始说明或相应公告。重新下载最新历史PB不能证明历史未被修订。

操作定义继续是供应商历史PB倒数。“完全无回填”尚未证明是需披露的证据限制，不等于已经证明BP全表无效，也不要求为课程报告自动建设整套历史财报数据库。若出现具体前视证据或要提出严格PIT主张，再按对应范围追加重构；若改变研究设计，须登记变更。其他关键数据条件仍按正式运行门槛执行。

## 并行工作边界

可以并行：独立文件/来源阅读、不同图表的校对、在同一锁定结果上做数值与文字审阅。

必须顺序：方法冻结之后的正式运行、影响同一面板的修改、信号先于未来收益连接、结果锁定先于结果性写作。

并行协作者使用同一方法版本和run_id，不编辑同一个文件；主执行者合并前检查冲突。未真正隔离上下文时，不把多种评语称为互盲或独立审稿。
