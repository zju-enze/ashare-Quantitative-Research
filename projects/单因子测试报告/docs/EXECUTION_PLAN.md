# 分阶段执行计划

状态：计划已编制；实际执行进度以[PROJECT_STATUS.md](PROJECT_STATUS.md)为准。统计口径以[RESEARCH_SPEC.md](RESEARCH_SPEC.md)为准，计划本身不代表阶段通过。

## 执行原则

- 按用户当轮指定的阶段范围推进。阶段通过意味着证据条件满足，不要求重复人工批准。
- 完成一个阶段即解释本阶段回答的问题；不要把所有检查压到报告写作之后。
- 输入不足时完成可继续的部分，列明具体文件/字段/时期及影响。不得把“没有上传”写成“本地不存在”。
- 只有P4以后才产生主实证结论；P0–P3的数量、缺失率等属于数据核查或诊断，不得包装为因子有效性。
- 以下文件路径是未来产物约定，不表示它们现在存在；目录按需创建，不生成一批空壳文件冒充进度。

## P0：接入项目与核实环境

**问题：我们正在操作哪个项目，读的是哪套程序和数据？**

动作：

1. 核实项目根目录、父级仓库规则、工作区现有文件，保留用户已有内容。
2. 定位课程教材、现有环境与qfbook；检查实际导入路径。用户上传README描述Python3.11及独立环境，但仍需本地验证。
3. 比较本地single_test.py的SHA-256与IMPLEMENTATION_REVIEW登记摘要。一致则确认同版；不一致则重新核对本地行为与审阅事项。本包不附原始源码，只有取得快照才做逐行差异比较；否则不宣称精确diff已完成，也不阻塞其余预检。只在指定课程范围查找报告生成脚本，未找到时记录检索范围，不推断全盘不存在。
4. 检查实际可用的学术skills及来源，记录读取入口。无匹配skill不阻塞数据工作。

产出：

- PROJECT_STATUS中的真实路径、环境/源码标识、教材版本、技能可用性。
- 源文件定位清单；必要时记录到outputs/preflight/source_inventory.csv。

通过条件：能够明确定位教材与现有实现，确认数据读取位置和本轮操作范围。若路径不可访问，提供可复核缺口，不伪造预检结果。

## P1：数据预检与方法冻结

**问题：现有数据能否支持附录指定研究，而不仅是“文件存在”？**

动作：

1. 按DATA_CONTRACT检查所需字段、键唯一性、逐期覆盖、日期范围与关键端点。
2. 查明PB分子与历史口径；区分负值、零值、非有限值和缺失。
3. 核对历史股票生命周期、ST/PT、停复牌、指数成员、行业区间。抽样检查状态变化附近日期。
4. 生成真实交易日历上的信号/入场/出场日期表；确定诊断和绩效各自可用范围。
5. 形成按股票池、月份的样本数量流转，列出未来收益缺失的具体原因及可解决程度。
6. 在未查看BP绩效的前提下，冻结可以落实的项目默认；不能落实的条目标清楚。

产出：

- outputs/preflight/data_inventory.csv：文件与字段可用性。
- outputs/preflight/calendar_audit.csv：三个日期、端点状态和是否完整。
- outputs/preflight/sample_flow.csv：逐步样本数量，不含推测结果。
- outputs/preflight/preflight_findings.md：已证实事实、尚待核实和建议处理。
- PROJECT_STATUS的方法版本/冻结记录。

通过条件：

- 正式股票池与成员时间范围可重建；不存在被隐瞒的当前快照或市值代理。
- 最终完整持有期有明确证据，未来缺失不会用于反向构造持仓。
- 主要未决数据问题具有处理政策；仍会改变结论的缺口明确阻断相应结果。

预检不要求先证明因子有效。若历史字段的点时性只能部分核验，应准确记录证据等级和结论限制，不冒称自行完成财报重建。

## P2：最小实现修正

**问题：如何让已有流水线遵守研究设定？**

动作：

1. 依IMPLEMENTATION_REVIEW的优先级处理时间表、收益构造、历史筛选和信号/收益样本分离。
2. 尽量保留现有MAD、中性化、WLS、IC、分层及两腿扣费逻辑；按需增加参数和输出，不另起一套重复研究框架。
3. 统一指数端点、缺月处理、初始净值和回撤；返回三个池的完整结果映射，避免仅保留最后一个池。
4. 记录每处行为变化、来源函数与理由。若采用项目内复制，保留来源与最小差异；不建立不可审计的运行时全局替换。

产出：

- 项目内最小适配/修正实现，位置按现有仓库惯例确定。
- outputs/validation/implementation_notes.md。
- 针对性核验结果；必要时tests/中保留少量可重复的风险测试。

必要核验案例：

- 月末、节假日后首交易日、数据末端不完整月份。
- 月中摘帽、指数换样、行业变更的生效边界。
- 人为移除某个未来收益，仅影响响应可观测标识，不改变已形成的信号与持仓。
- 多空两腿成本同时扣除，首期TO=1，第一期亏损计入最大回撤。
- 月份断裂不会被当成连续12个月，也不会自动产生零收益。

合成案例只能用于逻辑核验，并明确标记；不得进入实证目录或报告。

通过条件：核心风险已有可复核验证；可解释为何修正，而非只是输出接近教材示例。修正后数值不必与正文口径A一致。

## P3：因子截面诊断

**问题：BP在什么样的样本上被检验？**

动作：

- 生成D1、指定明确截面的一级行业中位数横向条形图、市值相关时序及汇总。
- 报告分母、正PB限制、未知行业/市值缺失造成的损失。
- 解释异常覆盖月份时，先核对数据与口径，再讨论可能经济原因。

产出：

- 可追溯的诊断数据和图，及对应解读笔记。
- 有证据的样本边界表述。

通过条件：行业图覆盖所有可识别一级行业；市值相关有均值和明确分母的同号比例；覆盖定义可复算。

## P4：基础三类检验

**问题：在统一设定下，BP是否具有方向一致的收益区分能力？**

动作：

- 运行三股票池的WLS、Rank IC和五层回测。
- 输出C1、C2与D1–D7；D1沿用已验证诊断，不重复发明口径。
- 检查方向、五层排序、极端组贡献、成本影响及三池差异。
- D4–D6全部提供；D6按预先登记或明确标为描述性的具体时段解释。

产出：

- outputs/runs/<run_id>/内的配置、样本摘要、月度原始结果、C1/C2、图及解读数据。
- PROJECT_STATUS中的运行登记与基础结论状态。

通过条件：表图同源；相同日期定义；每张图表有实际数字支持的解读。因子不显著不是阶段失败。

## P5：优秀线与适用范围

**问题：效果来自哪一端，在哪些时期、行业和规模范围成立？**

动作：

1. C3按研究约定的年度归属，区分完整和部分年度；比较多空收益与Q5超额。
2. C4在行业内重新五分层，使用既定残差范围、行业内基准和最低可计算门槛；保留不足样本记录。
3. D8展示五层风险收益；D9十层检验非线性；D10做市值三分域内十层。
4. 主结果与任何方法敏感性分开保存。IC衰减、额外统计推断或其他预处理只有在有具体问题时增加，不为凑“优秀”全部铺开。

产出：

- C3/C4、D8–D10的机器可读数据、图表和解释。
- 各行业/市值域样本数、有效月份、可比范围。

通过条件：优秀线图表齐全且有实质解释；缺失行业或月份明确列出；不通过删去困难域来制造稳健性。若真实数据不足以形成某必交结果，列为未满足，不能自动勾选通过。

## P6：结果驱动的中文报告写作

**问题：证据支持多强、多大范围的结论？**

前置：P4/P5结果已锁定。可更早写背景与方法，但结果、结论和摘要中的数字必须来自锁定运行。

动作：

- 使用WRITING_AND_SKILLS规定的阶段技能和附录B结构。
- 先组织“研究问题—证据—解释—边界”，最后写摘要。
- 每个关键数字定位至run_id、结果文件、股票池、时期与指标；每张表图就地解读。
- 将证据不足、反向、不一致、覆盖限制写入结论；不为了积极叙事改测试设定。

产出：

- report/bp_single_factor_report.md（未来完整报告，不在当前文档包内）。
- report/claim_evidence.csv或同等可追溯记录；无需重复管理性长文。
- 用户要求的最终导出格式；格式尚未明确时先交可编辑中文稿，不自行假定期刊投稿格式。

通过条件：必交表图均可定位；没有占位数字、教材样例混入或无证据的有效性断言。

## P7：一致性与交付验收

**问题：报告、数据产物、方法与代码能否相互核对？**

动作：

- 按ACCEPTANCE_CHECKLIST逐项核实证据。
- 检查三池日期、样本量、年化/超额定义、首尾部分年度及图轴；复核关键数字。
- 检查图表实际渲染、标签、字体、可读性与来源标注。
- 用一种适当的审阅框架做有定位的最终审阅；不强制重复多轮或制造问题数量。
- 只因具体未解决风险扩大检查；达到验收条件后停止可选测试。

产出：

- 已填写证据位置的验收清单和outputs/validation/final_review.md。
- 最终报告、结果索引和重现说明。
- PROJECT_STATUS中实际完成状态及未解决限制。

通过条件：所有必交项有实际产物与解读，任何尚未满足之处明确保留；不存在把“程序完成”当作“因子有效”的表述。

## 并行工作边界

可以并行：独立文件/来源阅读、不同图表的校对、在同一锁定结果上做数值与文字审阅。

必须顺序：方法冻结之后的正式运行、影响同一面板的修改、信号先于未来收益连接、结果锁定先于结果性写作。

并行协作者使用同一方法版本和run_id，不编辑同一个文件；主执行者合并前检查冲突。未真正隔离上下文时，不把多种评语称为互盲或独立审稿。
